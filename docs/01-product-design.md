﻿# X Memory 产品设计

## 1. 产品定位

X Memory 是本地优先的 X 内容记忆系统。它记录用户在首页时间线看到过的帖子，也记录用户主动打开详情页的访问事件，提供回看、搜索、跨域关联、AI 分析和可控同步。

它不是两个扩展的拼接。`rewind-for-x` 和 `x-footprints` 只作为两个采集适配器的实现基线。

## 2. 用户价值

- 首页刷新后仍能找回看过的内容；
- 从一条转帖或引用帖看到自己是否访问过原帖；
- 按帖子、作者、时间和关键词搜索；
- 对一个帖子、搜索结果或时间段请求摘要；
- 在授权的设备之间同步，而不让远端故障影响本地阅读；
- 让 Agent 通过稳定协议读取经过授权的记忆数据。

## 3. 产品边界

### 本期

- Chrome MV3 单一扩展运行边界；
- 时间线和详情页两个独立采集器；
- 独立本地数据域；
- 统一 Repository 和 Query Service；
- 历史栏所需的帖子关联查询；
- 迁移旧 `items`、`records` 和 `tombstones`。

### 后续

- 基于用户操作的全局 AI；
- 后台队列驱动的多域同步；
- 全局搜索索引；
- 日报和 Agent Gateway；
- 媒体资产和 OCR 的独立实体化。

## 4. 非目标

- 不抓取私信、Cookie、token、表单或浏览历史；
- 不绕过 X 的访问限制；
- 不在每张卡片渲染时请求 S3 或模型；
- 不把访问足迹默认上传；
- 不用 AI 结果覆盖原始帖子。

## 5. 关键体验

时间线卡片通过 `postId` 查询相关足迹。主卡片先渲染，足迹模块可以处于 `loading`、`empty` 或 `error`，不会阻塞主体。默认只展示摘要信息，完整事件在用户展开后读取。

## 6. 发布门槛

必须同时满足：本地采集、重启后读取、跨域关联、迁移幂等、错误降级和权限测试。真实 X 页面、AI endpoint、S3 和浏览器回收行为必须单独记录实测结果，未实测不得写成支持。
