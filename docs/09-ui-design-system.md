# X Memory UI 设计方案

> 版本 v2.0 · 2026-11-16 · UI 设计交付
> 配套高保真原型：`design/index.html`（单文件，浏览器直接打开）

---

## 一、设计愿景

把 X Memory 从「功能堆叠的工具面板」升级为「安静、可信、可掌控的个人记忆库」。

三个关键词：**清晰（Clarity）· 熟悉（Familiarity）· 可信（Trust）**

- **清晰**：信息分层，主次分明，任何时刻都知道自己在哪、发生了什么。
- **熟悉**：沿用用户已在 X 上形成的认知习惯（卡片流、胶囊筛选、时间线），把学习成本降到接近零。
- **可信**：本地优先不只是文案，而是一套可被看见的视觉语言——状态、边界、数据流都清晰可辨。

## 二、现状诊断

对现有 `apps/extension/popup.html / popup.css / popup.js` 的可用性审查结论：

| # | 问题 | 对用户的实际影响 | 严重度 |
|---|------|------------------|--------|
| 1 | `popup.css` 存在两套 `:root` 定义（深色 → 浅色整体覆盖），大量颜色被二次覆写 | 视觉意图不清，改一处颜色可能引发连锁错位；难以形成统一设计语言 | 高 |
| 2 | 设置页 20+ 字段连续平铺，仅靠 4 个文字标题分隔 | 首次配置时认知负荷高，用户不知道哪些必填、哪些已完成 | 高 |
| 3 | 所有操作结果只显示在顶部一行 11px 状态文字里 | 「同步成功」「日报已生成」等关键反馈极易被忽略，失败时无恢复路径 | 高 |
| 4 | 空状态只有一行图标 + 一句话 | 新用户不知道下一步该做什么，缺少引导 | 中 |
| 5 | 无加载骨架与过渡状态 | 读取本地数据或调用 AI 时界面「假死」，感知等待时间长 | 中 |
| 6 | 卡片类型仅靠颜色小字区分（青色=时间线），访问标识是绿色徽章 | 语义依赖颜色，色觉障碍用户难以区分；缺少形状/文字冗余编码 | 中 |
| 7 | 主导航、筛选、分页等控件的视觉权重与内容区接近 | 扫读时难以快速定位当前所在层级 | 中 |
| 8 | 筛选、导出、分页按钮样式不统一（胶囊/方块/文本混用） | 同一界面出现多种交互语言，增加判断成本 | 低 |

## 三、目标用户与核心场景

| 场景 | 用户想做的事 | 界面必须支持 |
|------|--------------|--------------|
| **A · 找回** | "刚刚在首页刷到一条内容，刷新后找不到了" | 打开即见记忆流；搜索正文中/作者/标签；按时间线/已访问筛选 |
| **B · 确认** | "这条转帖我当时有没有点进去看过原帖？" | 卡片上有明确的「访问足迹」标识，点击可查看访问次数与时间 |
| **C · 复盘** | "今天我关注的信息有什么规律？" | 每日日报视图：总体摘要 + 时间线/访问/兴趣方向三分组 |
| **D · 配置** | "我想接入 AI、S3 同步和日报推送" | 设置按能力分组，字段有说明、状态与校验反馈，隐私边界醒目 |

用户画像共性：熟悉 X 的交互模式、注重隐私、对等待和失败敏感、绝大多数操作在 **432px 宽的 popup** 内完成——因此方案坚持单列、紧凑但不拥挤的布局。

## 四、设计原则

1. **熟悉优先（Recognition over recall）**
   保留 X 的卡片流、胶囊筛选、头像 + 处理名 + @handle 的信息模式；不发明新隐喻。

2. **渐进式披露（Progressive disclosure）**
   默认展示摘要（正文前 6 行、图片缩略、访问次数），全文与完整事件在用户主动展开后出现——与产品文档§5 一致。

3. **状态可见（Visibility of system status）**
   本地 / 本地+S3、采集中 / 生成中 / 同步中、成功 / 失败 / 部分成功，都有专属视觉与文案，不用一行小字一走了之。

4. **隐私可感（Tangible privacy）**
   用「本地保险库」隐喻：本地徽章、数据流向示意、密钥字段的掩码与说明，让用户看得见数据边界。

5. **容错友好（Forgiving）**
   错误不只说"失败"，而说明原因与下一步；远端失败不阻塞本地阅读，并明确告知"本地数据仍可用"。

6. **一致性（Consistency）**
   所有颜色、间距、圆角、动效均来自统一 Token；同类控件只有一种标准样式。

## 六、视觉设计系统

### 6.1 色彩系统

从现有「X 蓝单色强调」升级为「中性基底 + 品牌主色 + 双语义强调色」。

| Token | 色值 | 用途 |
|-------|------|------|
| `--canvas` | `#F4F6FA` | 页面底色（略带冷调，让白卡浮起） |
| `--surface` | `#FFFFFF` | 卡片 / 面板 |
| `--surface-2` | `#F8FAFC` | 次级面板、输入框底 |
| `--line` | `#E4E9F0` | 分隔线、描边 |
| `--line-soft` | `#EFF3F7` | 弱分隔线 |
| `--ink` | `#16203A` | 主文本 |
| `--ink-2` | `#475569` | 次要文本 |
| `--ink-3` | `#7C8AA0` | 辅助文本 / 占位符 |
| `--brand` | `#4C5FD5` | 主按钮、激活态、品牌色（靛蓝 = 理性 + 信任） |
| `--brand-strong` | `#3A4AB5` | hover / pressed |
| `--brand-soft` | `#EEF1FE` | 激活背景、焦点底 |
| `--observe` | `#0E9384` | 时间线 / 观察（青绿） |
| `--observe-soft` | `#E4F6F2` | 观察标签背景 |
| `--visit` | `#C77A16` | 访问 / 足迹（琥珀） |
| `--visit-soft` | `#FDF2E0` | 足迹标签背景 |
| `--success` | `#12805C` / `--success-soft` `#E3F6EE` | 成功状态 |
| `--danger` | `#C8384B` / `--danger-soft` `#FCEBEE` | 错误 / 危险操作 |
| `--info` | `#2B7FC4` / `--info-soft` `#E8F3FC` | 提示信息 |

> **语义冗余**：观察用「时钟」图标 + 青色，访问用「脚印」图标 + 琥珀色，避免纯色彩编码。

### 6.2 字体排印

系统字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`

| 层级 | 字号 / 字重 / 行高 | 字距 | 用途 |
|------|-------------------|------|------|
| Display | 22px / 700 / 1.2 | -0.03em | 品牌主标题 |
| Title | 16px / 650 / 1.35 | -0.01em | 视图标题、分组标题 |
| Subtitle | 14px / 600 / 1.45 | 0 | 卡片作者名、小节标题 |
| Body | 13px / 400 / 1.65 | 0 | 正文、字段值 |
| Caption | 11px / 500 / 1.5 | 0 | 辅助说明、时间戳 |
| Micro | 10px / 700 / 1.4 | 0.08em | 徽章、 eyebrow、统计标签 |

规则：中文正文行高不低于 1.6；数字统计使用 `font-variant-numeric: tabular-nums` 对齐。

### 6.3 间距与布局

- **4px 基准网格**：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`
- 内容左右安全边距：`16px`（与 X 对齐）
- 卡片内边距：`12px 14px`；卡片间距：`8px`（比现有 10px 更紧，提升信息密度）
- 分组之间：`20px`；视图切换后首块上边距：`12px`
- 固定宽度 `432px`，最小高度 `560px`；内部单列滚动，顶栏与导航 sticky

### 6.4 圆角与阴影

| Token | 值 | 用途 |
|-------|----|----|
| `--r-sm` | 8px | 输入框、小徽章、图标按钮 |
| `--r-md` | 12px | 胶囊、筛选、分组卡 |
| `--r-lg` | 16px | 记忆卡片、面板 |
| `--r-xl` | 20px | 主容器、空状态卡 |
| `--r-pill` | 999px | 状态徽章、标签 |
| `--shadow-sm` | `0 1px 2px rgba(22,32,58,.05), 0 1px 3px rgba(22,32,58,.04)` | 分组卡 |
| `--shadow-md` | `0 4px 14px rgba(22,32,58,.07), 0 2px 4px rgba(22,32,58,.04)` | hover 抬升、toast |
| `--focus-ring` | `0 0 0 3px rgba(76,95,213,.20)` | 键盘焦点 |

> 阴影只用于「浮起」语义；同层级元素不加阴影，用描边区分。

### 6.5 图标

统一 16px / 1.8px 线性描边图标（内联 SVG，`stroke="currentColor"`）。核心图标：
时钟（观察）、脚印（访问）、放大镜（搜索）、刷新（采集）、齿轮（设置）、月亮/太阳（主题）、云上传（同步）、火花（日报）、盾牌（本地）、外链（打开原帖）、 chevron（展开/分页）。

### 6.6 动效

| Token | 值 | 场景 |
|-------|----|------|
| `--dur-fast` | 120ms | 按钮按下、颜色变化 |
| `--dur-base` | 180ms | hover、tab 切换 |
| `--dur-slow` | 280ms | 面板进出、空状态入场 |
| `--ease` | `cubic-bezier(.2,.8,.2,1)` | 统一缓动 |

- hover 卡片：`translateY(-1px)` + 阴影升级，不超过 180ms。
- 状态脉冲：本地心跳点 `2s` 循环，`opacity 1 → .45`。
- 必须尊重 `prefers-reduced-motion: reduce`，关闭位移动画，仅保留透明度。

## 七、核心界面设计

### 7.1 记忆流 Feed（默认视图）

1. **顶栏**：品牌 ✦ + 主标题 + LOCAL 徽章；右侧刷新、主题、设置三个图标按钮。
2. **概览条**：三个统计块（帖子 / 观察 / 访问），大号 tabular 数字 + 微型标签，用极细分隔线隔开——用户一眼掌握数据规模。
3. **搜索 + 筛选**：搜索框占满宽度，左侧放大镜，右侧清除按钮；下方 3 个胶囊筛选，激活态用品牌色实心。
4. **记忆卡片**：
   - 卡片头：左侧「观察 / 访问」类型标签（图标 + 文字 + 颜色三重编码），右侧相对时间；
   - 访问足迹作为独立的一行轻量提示条（"访问过 2 次 · 最近 3 小时前"），琥珀色背景，点击展开详情；
   - 作者行：40px 头像 + 14px 名字 + 13px @handle；
   - 正文：13px / 1.65，折叠 6 行，"展开全文"为文字按钮；
   - 媒体：单图全宽、多图 2 列，圆角 12px；
   - 卡片尾：左访问次数，右「打开原帖 ↗」次级按钮。
5. **分页**：上一页 / `第 X / Y 页` / 下一页，居中，禁用态明确。

### 7.2 每日日报 Digest

1. 顶部日期选择 + 主按钮「生成日报」，生成中显示内联进度（不用全屏遮罩）。
2. 结果状态区：成功显示绿色条 + 推送渠道（Telegram / Webhook），失败显示红色条 + 原因 + "重试"与"检查设置"两个动作。
3. 总体摘要用带左侧品牌色竖线的引言块呈现。
4. 三个知识分组用带图标的小标题 + 条目卡片（分类标签 + 摘要 + 证据 + 置信度）。
5. 底部统计脚注：时间线 N 条 · 访问 N 条 · 模型名。

### 7.3 设置 Settings

从"一长串字段"改为 **4 个分组卡片**：

- 每组有图标 + 标题 + 一句话说明 + 完成状态徽章（未配置 / 已配置）。
- 组内字段两列布局，label 在上、input 在下，帮助文字用小字跟在 label 后。
- 密钥类字段：密码掩码 + "留空保持不变"占位符 + 眼睛切换按钮（原型演示）。
- 危险动作（清空数据）使用 danger 描边按钮。
- 底部固定操作条：保存设置（主）+ 立即同步（次）。
- 隐私说明放在独立的柔和提示块中，带盾牌图标，不再是一行灰字。

## 九、状态设计

| 状态 | 视觉 | 文案策略 |
|------|------|----------|
| 首次加载 | 3 张骨架卡 + 概览条骨架 | "正在读取本地记录…" |
| 空数据 | 虚线圆角卡 + 插画图标 + 标题 + 一句引导 + 主按钮 | "记忆库还是空的 —— 打开 X 时间线，插件会自动保存你看到的帖子。" |
| 无搜索结果 | 同空状态，但图标为放大镜 | "没有找到匹配的内容 —— 换个关键词，或清除筛选试试。" |
| 采集中 | 刷新图标旋转 + 状态徽章变蓝 | "正在采集当前页面…" |
| AI 生成中 | 按钮内联 spinner + 骨架报告 | "正在归纳知识类别和兴趣方向，通常需要几秒…" |
| 成功 | 绿色 Toast + 顶部状态同步 | "日报已生成并推送至 Telegram" |
| 失败 | 红色 Toast + 卡片内错误块 + 重试动作 | "S3 同步失败：网络不可达。本地数据未受影响，可稍后重试。" |
| 部分成功 | 琥珀 Toast | "日报已生成，但推送失败：Webhook 超时。可在设置中检查地址。" |

原则：**任何错误都必须回答两件事——发生了什么、用户现在能做什么。**

## 十、可访问性

- 所有交互元素可 Tab 到达，焦点环用 `--focus-ring`，不移除 outline。
- 语义化标签：`nav / main / section / article / time`，tab 使用 `role="tablist" / aria-selected`。
- 状态变化用 `aria-live="polite"` 播报；错误用 `role="alert"`。
- 图标按钮必须有 `aria-label`。
- 正文与背景对比度 ≥ 4.5:1，大字 ≥ 3:1；辅助文字不使用低于 `--ink-3` 的浅色。
- 语义不依赖颜色：类型标签同时有图标和文字。
- `prefers-reduced-motion` 下关闭所有位移动画。

## 十一、落地建议与优先级

| 优先级 | 事项 | 说明 |
|--------|------|------|
| P0 | 清理 CSS 双主题覆盖，建立 Token 变量层 | 一次性替换现有 `:root`，所有组件改用变量，消除样式歧义 |
| P0 | 设置页分组重构 + 完成状态 | 复用原型中 `GroupCard` 结构，HTML 结构改动为主，JS 逻辑基本不变 |
| P0 | 状态反馈升级（Toast + 内联结果区） | 新增一个 `toast()` 工具函数，替换现有散落的 `status.textContent` |
| P1 | 卡片三重编码 + 访问足迹提示条 | 在 `record-template` 中增加图标与足迹块 |
| P1 | 骨架屏与空状态插画 | 新增模板，`renderItems()` 开头判断加载态 |
| P1 | 深浅主题切换 | Token 全部响应式定义，`data-theme` 切换并持久化 |
| P2 | 键盘快捷键（`/` 聚焦搜索、`Esc` 清除） | 提升高频操作效率 |
| P2 | Agent 接口状态面板 | 为后续 Agent Gateway 预留可见入口 |

> 原型中的 DOM 结构与 class 命名已尽量贴近现有实现，便于渐进式替换而非推倒重来。
