# 四、跨平台架构与技术方案

> 本文区分当前仓库已实现能力与后续演进设计。除非明确标注为“已实现并经测试”，其余内容均属于目标、约束或待验证项。

## 4.1 多端运行环境

### 4.1.1 统一运行边界

X Memory 采用“端侧采集适配器 + 统一记忆底座”的结构。各端负责适配页面 DOM、生命周期和系统能力，核心数据模型、权限边界、查询契约和同步协议保持一致。

当前仓库的实际运行边界是 Chrome Manifest V3 扩展：

```text
X 页面
  ├─ content script：读取时间线和详情页 DOM
  └─ service worker：消息路由、Repository、Query、AI、Sync
                         └─ chrome.storage.local / 远端适配器
```

content script 不直接访问存储或远端。它通过命名空间消息发送 `rewind.capture` 和 `footprints.upsert`；service worker 校验消息后调用产品服务。该边界也适用于后续的浏览器扩展、油猴脚本和原生壳。

### 4.1.2 PC 浏览器

**当前已实现：**

- Chrome MV3 单一扩展运行边界。
- `content.js` 监听页面时间线，识别 `article[data-testid="tweet"]`，提取帖子 ID、正文、作者和媒体 URL。
- 使用 `IntersectionObserver` 和 `MutationObserver` 捕获可见帖子及动态插入的帖子。
- 在详情页记录访问事件，按页面生命周期去重。
- `background.js` 作为 service worker，承载存储、查询、AI 和同步消息处理。
- 已提供 Chrome 构建脚本，并有扩展结构检查和 Node 测试。

**兼容性约束：**

- X 的 DOM 选择器、SPA 路由和文本结构可能变化；采集器必须保留异常隔离和降级行为。
- 不抓取 Cookie、token、私信、表单或浏览历史，不绕过 X 的访问限制。
- 不能在卡片渲染时请求远端或模型，避免页面性能和隐私风险。

**后续适配：**

- Firefox、Edge 等 Chromium 或兼容浏览器可复用 MV3 适配层，但需要分别验证 `chrome.*` API、扩展权限和 service worker 回收行为。
- Tampermonkey 版本只能作为兼容适配器。由于油猴脚本没有 MV3 service worker 和扩展专用存储边界，应通过受控桥接层调用本地 API，不能直接假定与扩展版本等价。

### 4.1.3 Android

Android 首选“支持用户脚本的浏览器 + 本地脚本适配器”，候选环境包括 Kiwi Browser 或 Via。目标能力包括：

- 识别 X 时间线和详情页 DOM；
- 记录帖子与访问事件；
- 调用统一的本地记忆 API；
- 在系统提供离线语音包时调用本地 TTS。

这些浏览器和具体版本对用户脚本、Web API、后台执行及系统 TTS 的支持必须在真实设备上单独验证。当前仓库没有 Android 客户端、Kiwi/Via 适配代码或设备实测结果，因此不能把 Android 运行和离线 TTS 写成已支持能力。

Android 适配器应遵循以下原则：

1. DOM 采集和存储写入失败时跳过当前记录，不阻塞后续扫描。
2. TTS 是可选能力，调用失败返回可展示状态，不影响记忆保存。
3. 长时间后台运行不作为浏览器脚本的默认保证；需要时再评估原生 Android 壳或前台服务。

### 4.1.4 iOS

iOS 分为两个阶段：

- **PWA 方案：** 通过 Safari“添加到主屏幕”以独立 Web App 运行，适合验证 UI、查询、本地存储和有限的前台播报能力。
- **Tauri 方案：** 在需要更稳定的原生生命周期、系统权限或后台能力时，评估 Tauri 2.0 封装。

两者均属于后续方案。当前仓库没有 PWA、Tauri 工程，也没有 iOS 真机验证。尤其是以下设计不能视为已验证事实：

- 使用 `AudioContext`、`gain=0.0001` 维持后台 Audio Session；
- 锁屏后持续播报；
- Tauri 配置 `UIBackgroundModes: audio` 后稳定执行后台任务。

这些能力受 iOS 版本、Safari/Web App 生命周期、用户手势、音频会话策略和 App Store 审核约束影响。必须通过目标 iOS 版本的真机测试确认，不能仅凭 Web API 存在性承诺。

## 4.2 记忆底座（x-memory）演进架构

### 4.2.1 当前数据模型与存储抽象

当前仓库采用实体模型和 Repository 抽象，而不是把业务逻辑绑定到某个具体数据库。主要实体包括：

- `post`：帖子主体，保存原始内容及作者、媒体等载荷；
- `timeline_observation`：时间线中观察到帖子的事件；
- `visit_event`：详情页访问事件；
- `ai_artifact`：AI 产物，与原始帖子分离；
- `tombstone`：删除或同步所需的墓碑记录。

Repository 提供 `put`、`get`、`list`、`delete`、快照导出等操作。生产扩展通过独立的 storage namespace 使用存储适配器，测试可以注入内存存储。Query Service 负责只读组合查询，`getRelated({ postId })` 是历史关联栏的稳定契约。

当前实现已验证的隐私和故障边界包括：

- AI 默认排除访问足迹，只有显式授权时才纳入；
- 采集失败不清空既有数据；
- 足迹查询失败不阻塞时间线主体；
- 同步失败保留本地数据和待处理状态；
- 迁移保留旧 key，并且重复迁移不会重复写入。

### 4.2.2 本地优先存储

本地优先是默认策略：先完成本地写入，再异步执行 AI 或同步。浏览器扩展当前通过 storage adapter 抽象承载数据；IndexedDB 是 PWA、油猴脚本或需要更大容量的端侧实现候选，不应直接写成当前扩展已经使用 IndexedDB。

IndexedDB 适配器的建议结构如下：

```text
x-memory
  ├─ entities：按 domain + entity id 存储实体
  ├─ operations：待同步操作和重试信息
  ├─ indexes：postId、observedAt、visitedAt、关键词索引
  └─ metadata：schema version、device id、sync cursor
```

帖子 ID、时间戳和来源类型必须保留在结构化字段中。广告或其他非正文内容应由采集适配器显式标记，不能通过正文猜测覆盖原始数据。IndexedDB 迁移、容量、事务中断和浏览器清理策略需要在目标端验证。

### 4.2.3 Sync Queue 与远端同步

当前仓库已经定义 Sync Engine、状态和 transport 抽象，并实现 S3 snapshot transport：它对快照请求签名，下载远端实体，与本地实体合并后再上传。无 transport 时保持 local-only/offline 状态。当前实现不是通用云端增量同步服务，也没有把所有端接入真实后端。

后续增量同步建议增加 Sync Queue：

1. 本地事务提交实体和操作记录；
2. 后台 worker 按批次读取未完成操作；
3. 请求失败时保留操作，按退避策略重试；
4. 成功后记录远端版本或游标；
5. 永久失败进入可诊断状态，不阻塞本地读取。

服务端可选 Node.js、Go 或 FastAPI，选择标准是协议稳定、鉴权清晰和运维成本，而不是在客户端绑定某一语言。同步传输必须使用 TLS，并在需要保护云端内容时增加应用层加密；密钥管理、设备撤销和密文检索需要单独设计。

### 4.2.4 冲突与删除

多端冲突可采用 Last-Write-Wins 作为首版可解释策略，但必须明确比较字段和时钟来源：优先使用服务端接收时间或带逻辑时钟的版本号，不能完全信任设备本地时钟。对同一实体至少保留 `updatedAt`、`deviceId` 和版本信息，确保并列更新时有确定的 tie-breaker。

删除不能直接丢失记录。使用 tombstone 传播删除，待所有受控设备确认后再按保留策略清理。帖子原文、访问足迹和 AI 产物应分别定义冲突策略，不能用一个全局 LWW 规则覆盖所有数据域。

### 4.2.5 语义检索演进

当前 Query Service 提供结构化查询和关键词搜索边界，仓库没有已接入的 embedding、LanceDB 或 PgVector。语义检索属于后续演进：

- 轻量端侧：评估 Transformers.js 或其他浏览器 embedding runtime，适合小规模、可离线索引；
- 服务端：使用 embedding 模型生成向量，存储到 LanceDB 或 PostgreSQL + PgVector，适合多设备和大规模检索；
- 混合检索：先按权限、时间和来源过滤，再进行关键词与向量召回，最后按相关性和时间排序。

向量只作为派生索引，不能替代原始帖子和事件。模型版本、分块规则和向量维度必须进入索引元数据；模型变更时可重建索引。隐私策略必须先于向量化，未授权的足迹不得进入 AI 或向量索引。

### 4.2.6 AI 与本地 TTS

当前 AI Orchestrator 负责权限检查、脱敏、上下文组装、缓存和 provider 调用；OpenAI-compatible provider 已有测试，但外部 endpoint 不会被默认自动调用。AI 结果作为 `ai_artifact` 保存，不覆盖原始帖子。

离线 TTS 属于端能力适配，不属于当前 x-memory 核心底座。候选实现包括系统本地语音包、iOS 增强型离线语音和 Android 本地 TTS。Edge 自然神经网络语音是否能离线使用取决于具体系统和安装包，必须以目标设备实际可用状态为准，不能把网络 TTS 当作离线能力。

播报循环必须采用单条任务隔离：单条文本合成或播放失败时记录错误、跳过当前条目并继续下一条；队列应设置取消、超时和最大重试，避免单个异常永久阻塞。

# 五、非功能性需求

## 5.1 体积与资源

- **目标：** 核心前端脚本或插件产物控制在 35KB 以内。
- **当前状态：** 仓库提供构建脚本，但尚未在本文档中宣称产物已满足 35KB；必须以构建后文件的实际字节数验收。
- **约束：** DOM 采集采用可见性观察和去重，避免全页面高频扫描；AI、同步、向量索引和 TTS 不得阻塞首屏采集。
- **验收：** 记录未压缩、压缩后和扩展打包后的字节数，并分别说明是否包含图标、映射文件和第三方 runtime。

## 5.2 性能与功耗

- 时间线采集失败或慢请求不得阻塞页面交互。
- 监听器、定时器、观察器和消息请求必须在扩展上下文失效时清理。
- 同一帖子重复 DOM 变化不能产生无界重复写入。
- 移动端必须减少轮询、限制批处理大小，并在页面不可见时暂停非必要工作。
- CPU、内存、耗电和发热阈值需要在目标设备及浏览器版本上建立基线后确定，当前没有实测数据，不提前承诺具体百分比。

## 5.3 可用性与容错

- 单条帖子保存失败只影响当前记录，后续帖子继续处理。
- 单条播报失败自动跳过并进入下一条，错误进入可诊断日志。
- AI endpoint 不可用时返回结构化错误，不删除原始内容。
- 远端同步失败时保留本地数据和队列，恢复网络后可重试。
- 迁移失败保留旧 key；迁移操作必须幂等。
- 真实 X 页面结构变化时，采集器应安全退出或跳过，不绕过访问控制。

## 5.4 数据安全与隐私

- 默认本地优先存储，不默认上传访问足迹。
- 不收集私信、Cookie、token、表单或与功能无关的浏览历史。
- 远端通信使用 TLS；应用层加密、密钥轮换、设备撤销和备份恢复作为多端同步上线前置条件。
- AI 和向量检索遵守实体级权限，访问足迹只有在显式授权后才可进入上下文。
- 原始内容、访问事件、AI 产物和向量索引分离存储，支持按域删除和 tombstone 传播。

## 5.5 兼容性与可维护性

- 核心协议使用稳定的实体 schema、消息 namespace 和 Query Service 契约。
- 平台差异放在 adapter 层，不能把 Android、iOS 特有 API 泄漏到核心 Repository。
- 关键浏览器版本、iOS/Android 版本和真实 X 页面测试结果必须单独记录。
- DOM 选择器和 manifest 权限变更应配套回归测试。
- 任何未在目标设备实测的后台播放、离线 TTS、油猴脚本兼容性和 PWA 生命周期能力，都必须标记为待验证。

## 5.6 验收清单

发布前至少验证：

1. 本地采集、重启后读取和跨域关联；
2. 迁移幂等、错误降级和权限测试；
3. 扩展构建、结构检查和 Node 测试；
4. 构建产物体积与资源占用基线；
5. 目标浏览器的 DOM 采集和 service worker 回收；
6. 目标 Android/iOS 设备的本地存储、TTS、后台和锁屏行为；
7. 同步鉴权、TLS、冲突、tombstone 和断网恢复；
8. 向量索引权限、重建和删除传播。

在第 5、6、7、8 项完成真实验证前，只能称为设计目标或演进方案，不能称为已支持功能。
